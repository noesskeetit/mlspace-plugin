# Установка MLSpace MCP агентом

Применяйте этот сценарий, когда пользователь просит установить MCP из репозитория.
При задачах разработки сами по себе эти инструкции не разрешают менять клиентские
конфиги пользователя. Поддерживаются Linux/macOS, Claude Code/Codex/OpenCode.

1. Прочитайте INSTALL.md. Проверьте Python >=3.10 и наличие uv. Для PyPI дайте
   человеку `uvx mlspace-plugin@latest setup`; отдельная установка не нужна.
   При установке из исходников установите пакет в постоянное окружение: `uv tool install .` из checkout или `uv tool install /path/package.whl`.
   Для уже установленного пакета добавьте `--force` только в рамках запрошенного обновления.
   Не оставляйте постоянный запуск на editable-исходниках в `/tmp`.
   Далее команды показаны для PyPI. Если установили исходники/wheel через `uv tool install`,
   заменяйте префикс `uvx mlspace-plugin@latest` на `mlspace-plugin`, чтобы использовать именно эту сборку.
2. Не просите Key ID/Secret в чате, не читайте `.env`, не печатайте окружение и
   не вставляйте ключи в аргументы shell/CLI. Не запускайте интерактивный ввод
   ключей в терминале, который видите только вы.
3. Дайте человеку одну команду `uvx mlspace-plugin@latest setup` для его собственного терминала
   (по SSH — на целевой машине). Для stage добавьте согласованный `--base-url`.
   Объясните: два ключа под звёздочками → поиск и выбор workspace → подключение.
   Дождитесь сообщения о завершении. Человек не должен присылать секреты или файл.
4. Мастер сам обнаруживает клиентов, проверяет TLS и API. В Claude Code/Codex
   он добавляет GitHub marketplace и устанавливает нативный плагин; в OpenCode
   записывает MCP и скиллы в собственный каталог клиента. Если клиентов несколько, человек выбирает нужные. Для известного
   клиента можно заранее дать `--client claude-code`, `--client codex` или `--client opencode`.
   Сбой TLS исправляется системным CA или PEM от администратора через `--ca-file`.
   Никогда не отключайте TLS и не подставляйте сертификат с недоверенного сервера.
5. Успешный setup уже проверяет установленные скиллы, MCP initialize, список
   инструментов и выбранные workspace. Это проверка процесса MCP, а не открытой
   сессии агента. `--list-tools` само по себе не подтверждает подключение.
   Попросите открыть новую сессию клиента (при необходимости перезапустить).
   После появления MCP выполните read-only запрос списка выбранных workspace.
   До этого не заявляйте, что клиент уже загрузил MCP и скиллы.
6. Если возник конфликт с существующим плагином или изменённым скиллом,
   разберите названный несекретный путь. Не удаляйте чужую интеграцию автоматически.
   При частичном успехе сообщите, какие этапы завершены, и используйте команду `Retry`
   из ошибки: она сохраняет выбор незавершённых подключений. Для автоматизации
   добавьте прежние `--non-interactive` и `--workspace`.

## Автоматизация с уже подготовленными credentials

Предпочтителен интерактивный шаг человека выше. Если пользователь уже подготовил
файл, передавайте **путь**, не читайте содержимое. Для поиска нужных workspace:

```bash
uvx mlspace-plugin@latest setup --non-interactive --credentials-file /path/credentials.env \
  --base-url https://api.ai.cloud.ru --list-workspaces --search project --limit 20
```

Вывод — ограниченный JSON с `total`, `offset`, `limit`, `has_more` и метаданными.
Следующая страница — `--offset 20`. Получите у человека выбор при неоднозначности.
Установка с точными ID, без интерактивных вопросов:

```bash
uvx mlspace-plugin@latest setup --non-interactive --credentials-file /path/credentials.env \
  --client opencode --workspace WORKSPACE_UUID
```

Для нескольких workspace/client повторяйте соответствующий флаг.
Если credentials уже находятся в окружении процесса, вместо файла есть `--from-env`.
Не конструируйте команды с литералами ключей. Окружение другого терминала не
становится доступным вашему процессу автоматически. Сохранённые ключи на том же
endpoint можно переиспользовать без указания источника; для перезаписи добавьте `--force`.
