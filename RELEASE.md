# Выпуск MLSpace Plugin

Один релиз содержит Python-пакет `mlspace-plugin` и ZIP с MCP и скиллами.
Публикация новой версии не должна перезаписывать существующий релиз.

1. Обновите версию в `pyproject.toml` и `src/mlspace_mcp/__init__.py`, затем
   `uv lock` и `uv run python scripts/gen_plugin.py`. Обновите примеры имён wheel/ZIP
   в инструкциях, если версия присутствует в имени файла.
2. Выполните проверки из `CONTRIBUTING.md` на Linux и macOS.
3. Соберите пакет (в командах ниже замените 0.3.1 на выпускаемую версию):

```sh
uv build --out-dir dist/release-0.3.1
uv run python scripts/build_plugin.py --output dist/plugin-release-0.3.1
```

4. Просмотрите содержимое wheel, sdist и ZIP. В них не должно быть credentials,
   локальных конфигов, кешей, внутренних отчётов или приватных адресов.
   Установите wheel в чистое окружение; проверьте `--version`, `setup --help`,
   `--list-tools` и запуск stdio. Проверьте установку MCP и скиллов на изолированных
   конфигурациях клиентов. Локальные mock-тесты не заменяют проверку доступа к API.
5. Публикуйте только два проверенных Python-архива. Токен задаётся в окружении
   `UV_PUBLISH_TOKEN` средствами вашего хранилища секретов, не аргументом команды:

```sh
uv publish --trusted-publishing never dist/release-0.3.1/mlspace_plugin-0.3.1-py3-none-any.whl dist/release-0.3.1/mlspace_plugin-0.3.1.tar.gz
```

6. Проверьте версию и SHA256 обоих файлов через PyPI JSON API; проверьте установку
   `uvx --from mlspace-plugin==0.3.1 mlspace-plugin --version` из нового кеша.
7. Только после проверки точной версии в PyPI обновите рабочую ветку GitHub
   marketplace и создайте тег релиза. До этого проверяйте изменения на отдельной
   release-ветке или локальном Git marketplace: main не должен ссылаться на
   отсутствующий пакет. ZIP и SHA256SUMS приложите к тому же релизу.
8. В чистом HOME выполните публичный setup, проверьте source/version нативных
   плагинов, MCP handshake и загрузку скиллов клиентами. Используйте тестовые
   credentials и локальный HTTPS-стенд; не выполняйте записи в реальном tenant.

Пакет не проверяет обновления в фоне. Для PyPI пользователь повторяет
`uvx mlspace-plugin@latest setup --force`: обновляются сервер и неизменённые скиллы.
Claude Code и Codex получают нативный плагин через marketplace этого репозитория;
OpenCode — MCP и скиллы в собственном каталоге. Политики автообновления клиентов
не меняются. Не обещайте одинаковое фоновое обновление во всех клиентах.

Перед открытием существующего приватного Git-репозитория проверьте также его
историю. Проверка wheel и sdist не является проверкой старых Git-коммитов.
Для нового публичного репозитория можно использовать проверенный sdist без истории.
