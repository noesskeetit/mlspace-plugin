# Разработка

Нужны Python 3.10+ и uv; поддерживаются Linux и macOS.

```sh
uv sync --extra dev
uv run pytest
uv run ruff check src scripts tests
uv run mypy src
uv run python scripts/gen_plugin.py --check
```

Тесты API используют поддельные credentials и HTTP mock. TLS-тест поднимает
локальный HTTPS-сервер: среда должна разрешать loopback-сокеты. Проверки клиентов
используют временные домашние каталоги; без установленного клиента эти проверки
пропускаются. Не используйте настоящие ключи для тестов и не меняйте пользовательские
конфиги при разработке.

Код сервера находится в `src/mlspace_mcp`, сценарии — в `plugin/skills`.
`init_cli.py` реализует команду `setup`; имя Python-модуля остаётся внутренним.
После изменения версии регенерируйте манифесты: `uv run python scripts/gen_plugin.py`.
После изменения OpenAPI: `uv run python scripts/gen_body_schemas.py`.
Добавляйте проверку наблюдаемого поведения для исправлений и новых функций.

Локальный `.env` не загружается автоматически. Для ручного запуска выберите
доверенный файл через `MLSPACE_ENV_FILE`; никогда не добавляйте его в коммит.
В сообщения об ошибках не включайте ключи, токены, тела авторизации или полный
дамп окружения. Для сообщения об уязвимости используйте приватный канал владельца
репозитория; публичный issue не должен содержать действующие credentials.

## Фидбэк и предложения

Создайте [Issue](https://github.com/noesskeetit/mlspace-plugin/issues): задача → ожидаемое поведение → фактический
результат. Добавьте версию плагина, ОС, клиент и минимальные шаги воспроизведения.
Для идеи по удобству работы достаточно конкретного пользовательского сценария.
Не включайте credentials, приватные адреса, персональные данные или полный дамп логов.

Для изменения кода создайте ветку и [Pull Request](https://github.com/noesskeetit/mlspace-plugin/pulls). Опишите,
какую задачу решает изменение и как вы его проверили. Держите изменение в рамках
одной задачи, чтобы его было проще проверить и принять.

## Присылайте свои скиллы

Пользовательские скиллы приветствуются: они превращают повторяющиеся задачи
MLSpace в понятные агенту сценарии и улучшают повседневную работу с платформой.

1. Опишите задачу и результат: когда агент должен использовать скилл и как
   проверить, что задача выполнена.
2. Добавьте `plugin/skills/mlspace-<сценарий>/SKILL.md`. Возьмите соседний скилл
   как пример frontmatter и структуры; используйте существующие MCP-инструменты.
3. Используйте вымышленные данные в примерах. Не сохраняйте ключи, личные workspace
   или конфигурацию вашей организации. Для операций записи сохраните подтверждения,
   которые требует сервер; не обходите их инструкциями скилла.
4. Выполните `uv run pytest tests/test_skills.py` и приложите к предложению
   короткий пример использования. Отдельно укажите, что проверено локально,
   а что — на реальном API.

Если не хочется писать SKILL.md самостоятельно, создайте Issue со сценарием:
что вы делаете вручную, где теряете время и какой результат хотите получать.
