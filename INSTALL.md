# Установка MLSpace MCP: macOS и Linux

Нужны Python 3.10+, `uv` (команда `uvx`), Git для нативных плагинов,
актуальный Claude Code, Codex или OpenCode,
Cloud.ru Key ID и Key Secret. Windows пока не поддерживаем.

Первая установка из PyPI выполняется одной командой:

```bash
uvx mlspace-plugin@latest setup
```

`uvx` загружает пакет и запускает мастер. В конфиге клиента сохраняется команда
запуска конкретной версии, а не путь к временному окружению.

В каталоге скачанного репозитория установите пакет в постоянное окружение:

```bash
uv tool install .
mlspace-plugin setup
```

Если пакет уже установлен: `uv tool install --force .`.
При установке из wheel: `uv tool install /путь/к/mlspace_plugin-0.3.0-py3-none-any.whl`.
Не используйте editable-установку из `/tmp` для постоянной работы.
Далее команды показаны для PyPI. После установки исходников или wheel через
`uv tool install` заменяйте `uvx mlspace-plugin@latest` на `mlspace-plugin`,
чтобы использовать именно установленную сборку.

Мастер:

1. Найдёт установленные клиенты. Один подключит автоматически, для нескольких
   предложит выбор. Если клиент не найден, можно указать путь к исполняемому файлу.
2. Попросит **только Key ID и Key Secret**. Вставляйте значения без `MLSPACE_...=`;
   звёздочки показывают ввод. Ключи создаются в консоли Cloud.ru в профиле, «Ключи доступа».
3. Загрузит воркспейсы. Печатайте имя, проект или ID для поиска. Стрелки перемещают
   курсор, пробел отмечает, Enter завершает выбор. Ctrl-U очищает поиск; выбор сохраняется.
4. Проверит выбранные воркспейсы и сохранит настройки.
5. Для Claude Code и Codex добавит marketplace этого GitHub-репозитория и установит
   `mlspace@mlspace`. Для OpenCode запишет MCP-подключение и скиллы в
   `~/.config/opencode/skills` (учитывается `XDG_CONFIG_HOME`).
6. Сверит скиллы, запустит MCP и проверит инструменты и выбранные воркспейсы.

Если настройка клиента не завершилась, проверенные ключи остаются сохранёнными.
Мастер перечислит установленные клиенты; устраните причину и выполните напечатанную
команду `Retry`. Она сохраняет выбор клиентов, включая незавершённые подключения.

Откройте новую сессию выбранного клиента; если MCP не появился, перезапустите клиент.
Сервер запускается клиентом автоматически. Первый запрос:

> Покажи выбранные воркспейсы и запущенные задачи, ничего не меняй.

## Stage и корпоративные сертификаты

```bash
uvx mlspace-plugin@latest setup --base-url https://mlspace-stage.example.com
```

Настройка и работа сервера используют системные доверенные сертификаты: Keychain
на macOS, OpenSSL trust store на Linux. Если корпоративного CA там нет, мастер
попросит путь к PEM, полученному у администратора. Можно указать заранее:

```bash
uvx mlspace-plugin@latest setup --ca-file /путь/к/corporate-ca.pem
```

Мастер сохранит копию CA рядом с настройками. Переменные текущего терминала и
ручной wrapper для следующих запусков не нужны. Проверка TLS всегда включена;
сертификат, скачанный с недоверенного endpoint, автоматически не принимается.
Если задан SSL_CERT_DIR, мастер попросит убрать эту переменную на время настройки
и передать доверенный PEM через --ca-file: каталог из окружения не переносится
автоматически в процесс клиента.
Ошибка сети/сертификата не превращается в запрос ручного x-api-key.

## Повторная настройка

```bash
uvx mlspace-plugin@latest setup --force
uvx mlspace-plugin@latest setup --force --replace-credentials
uvx mlspace-plugin@latest setup --force --client opencode
uvx mlspace-plugin@latest setup --force --client-path opencode=/полный/путь/opencode
```

`--force` повторяет настройку с сохранёнными ключами на прежнем endpoint.
`--replace-credentials` запрашивает новые. При смене endpoint ключи запрашиваются
заново, если источник явно не выбран. `--client` можно повторять.
Посторонние MCP, комментарии JSONC и дополнительные пользовательские скиллы сохраняются.
Если в OpenCode уже есть другое подключение `mcp.mlspace` или отличающиеся скиллы
с именами из пакета, мастер **до ввода ключей** покажет все эти конфликты вместе.
Для подключения выберите `r`, чтобы сохранить резервную копию конфига и заменить
только `mcp.mlspace`. Для каждого конфликтующего скилла доступны:

- `k` — оставить свою версию активной и исключить её из обновлений плагина.
  Этот выбор сохраняется для последующих запусков setup. Проверка сообщит,
  что пользовательская версия не проверялась на совпадение с релизом.
- `r` — сохранить весь каталог скилла, включая вспомогательные файлы, в резервной
  копии и установить пакетный `SKILL.md`.
- Enter — отменить настройку без замены конфликтующих файлов.

Резервные копии находятся в `backups/setup-*` рядом с `install-state.json`
в каталоге настроек MLSpace, **вне каталогов скиллов**; мастер печатает точный путь.
Они создаются перед заменой после проверки credentials. Если резервное копирование
не удалось, конфликтующие файлы не заменяются. Отличие от пакета само по себе
не означает ручное редактирование: это может быть файл от старой установки.
`--force` не разрешает замену конфликтов. В `--non-interactive` мастер перечисляет
их и останавливается; для выбора запустите ту же команду в своём терминале без этого флага.

Уже установленный `mlspace@mlspace` из этого репозитория переиспользуется.
Если имя marketplace занято другим источником или есть отдельная прямая регистрация
MLSpace в Claude/Codex, мастер остановится до ввода ключей. Разберите указанное
подключение; мастер не удаляет его автоматически.

## Где ключи

`~/.config/mlspace-plugin/.env` (или каталог из `XDG_CONFIG_HOME`): права файла `0600`,
каталога MLSpace `0700`. В конфиге клиента — только путь и команда запуска.
Несекретный указатель `~/.config/mlspace-plugin/credentials-path.json` хранит путь
к выбранному файлу. Поэтому `--path` и нестандартный `XDG_CONFIG_HOME` не требуют
wrapper или экспорта переменных перед каждым запуском клиента.
Это не шифрование: процессы того же пользователя и администратор могут прочитать
файл. Не отправляйте его в чат и не добавляйте в Git. x-api-key получается автоматически
и не сохраняется. Доступ к каждому выбранному workspace проверяется, но это не
проверка прав на каждую возможную операцию API.

## Linux по SSH / установка агентом

Запустите `uvx mlspace-plugin@latest setup` в своей SSH-сессии. Браузер и графическая среда не нужны.
Если установкой занимается агент, он готовит пакет, а ключи вы вводите сами в своём
терминале. После завершения сообщите агенту «готово», без ключей и содержимого `.env`.

Для настройки только credentials без установки клиентов/скиллов есть `--config-only`.
Для особого офлайн-сценария: `--config-only --no-verify --workspace UUID`;
результат явно отмечается как непроверенный и клиенты не подключаются.
Обычный мастер сохраняет файл только после успешной проверки.

## Обновление пакета и скиллов

```bash
uvx mlspace-plugin@latest setup --force
```

Мастер переиспользует ключи, предложит выбор workspace и обновит все сохранившиеся
подключения, созданные им ранее. `--client` добавляет новые подключения.
Удалённые подключения не восстанавливаются автоматически.

Claude Code и Codex обновляют нативный плагин через свой менеджер; MCP и скиллы
приходят из одного релиза. OpenCode обновляет команду MCP и свои скиллы.
Для отличающихся конфигов и скиллов OpenCode мастер предлагает выбор, описанный выше.
Дополнительные скиллы с отдельными именами, в том числе `mlspace-*`, не мешают
установке и проверке. Скиллы, оставленные через `k`, не обновляются плагином.
Кеш нативного плагина принадлежит менеджеру клиента: свои правки храните отдельно.

Для постоянной установки сначала `uv tool upgrade mlspace-plugin`, затем
`mlspace-plugin setup --force`. Сборка из исходников должна соответствовать
версии публичного marketplace; для разработки используйте `--config-only`
или изолированную тестовую установку.

Собственного фонового обновления нет. Настройки автообновления Claude/Codex
мастер не меняет. Установка и проверка конкретной версии требуют доступа к GitHub
и PyPI. Если публикация релиза ещё не завершена, setup сообщает об ошибке;
повторите его после завершения публикации.
